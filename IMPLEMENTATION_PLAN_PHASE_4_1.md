### 1.2 Threat Model Mapping

Per `architecture-design.md` §1.1, this layer maps to:

| Attack Goal | What It Means | Countermeasure |
|---|---|---|
| **Action hijack** | Agent commits, deletes, sends, or charges without user intent | L4 HITL Gate + L3 BYOC + **4.1 Function-Calling Detector** |
| **Quiet commands** | Prompt tells agent to skip confirmation or act silently | L3 BYOC `never_override_system_prompt` + L4 HITL + **4.1 Function-Calling Detector** |

The function-call hallucination detector adds a new dimension: it catches fabricated tool calls that *look* structurally valid (correct tool name, plausible parameter shape) but are *semantically* injected — e.g., a tool call that the LLM never actually proposed, or parameters that were modified by prompt injection.

### 1.3 Granite Guardian Capability

Granite Guardian 8B reports **0.79 BAcc on function-calling hallucination detection** (recommendation.md §6). It evaluates whether:
- The proposed tool call was actually generated by the model or fabricated by injection
- The tool call parameters are legitimate or injected fabrications
- The tool call is consistent with the model's intent vs. an injection payload

The check is performed via the Guardian API with a special function-hallucination mode, which analyzes the tool call metadata (name, arguments) separately from the general safety scoring.

## 2. Architecture & Design

### 2.1 Pipeline Position

The function-call hallucination check sits **between Guardian fast-mode (L2) and BYOC (L3)** in the proxy pipeline:

```
Current Pipeline:
  PII Scan → Guardian Fast → BYOC → HITL → Forward

New Pipeline (Phase 4.1):
  PII Scan → Guardian Fast → Function-Call Detector → BYOC → HITL → Forward
```

The detector only activates when **both** conditions are met:
1. The LLM response contains tool invocations (extracted from `tool_calls` field or similar structure)
2. The response has **low-trust provenance** (`trust_level < 0.5`)

### 2.2 Decision Matrix

```python
def should_check(tool_calls: list[dict], provenance: Provenance) -> bool:
    """Determine whether the function-call detector should run."""
    if not tool_calls:
        return False  # No tool calls → nothing to check
    if not provenance.is_low_trust:
        return False  # High trust → skip (Guardian fast-mode already passed)
    return True  # Low-trust + tool calls → check
```

### 2.3 Guardian API Integration

The detector calls the **same Guardian API** as the existing `GuardianGuard`, but with a different payload shape:

```json
{
    "tool_calls": [
        {"name": "terminal", "arguments": "cat /etc/shadow"}
    ],
    "model": "granite4.1-guardian",
    "check_type": "function_hallucination"
}
```

Guardian returns:
```json
{"score": "yes"}   // Legitimate tool call → ALLOW
{"score": "no"}    // Hallucination detected → BLOCK
```

### 2.4 Fail-Safe Behavior

Following the existing `GuardianGuard` pattern (4 fail-safe strategies), the function-call detector uses a configurable `function_call_fail_strategy`:

| Strategy | Behavior | Use Case |
|---|---|---|
| `block` (default) | Block request on Guardian error/timeout | Production — safest default |
| `warn` | Allow request, log warning | Staging / development |
| `allow` | Always allow on error | Development — zero friction |
| `fallback` | Run local heuristic check | Fallback when cloud is unreachable |

### 2.5 Configuration Model

The detector is configured via YAML rules file (`guardrail-config/function_call_rules.yaml`):

```yaml
# Function-Calling Hallucination Detection Rules
# This layer checks whether LLM-proposed tool calls are legitimate
# or injected fabrications. Runs only on low-trust provenance.

rules:
  # Trust-level threshold for enabling the detector
  low_trust_threshold: 0.5

  # Fail-safe strategy when Guardian API is unreachable
  fail_strategy: "block"

  # Tool-level overrides: per-tool configuration
  tool_overrides:
    terminal:
      enforce: true          # Always check, regardless of trust level
    browser_navigate:
      enforce: true
    delegate_task:
      enforce: false         # Skip for delegated tasks (reduces false positives)
    web_search:
      enforce: false

  # Minimum tool call confidence (sent to Guardian as context)
  min_confidence: 0.3

  # Timeout for Guardian function-hallucination check (seconds)
  timeout_seconds: 5
```

### Step 2: Create `gateway/core/function_call_detector.py`

**File:** `gateway/core/function_call_detector.py`  
**Purpose:** Core detector class that evaluates tool calls for hallucination  
**Pattern:** Follows `GuardianGuard` structure (same API integration pattern)

#### 2.1 Module Structure

```python
"""
Function-Calling Hallucination Detection

Pre-execution Guardian pass to evaluate whether model-proposed tool calls
are legitimate or injected fabrications.

Granite Guardian: 0.79 BAcc on function-hallucination detection.
Runs only when: (1) response contains tool calls AND (2) low-trust provenance.
"""

import re
import yaml
import logging
import httpx
from typing import Any, Dict, List, Optional
from dataclasses import dataclass, field

from gateway.core.guardrail import GuardianGuard, SafetyDecision
from gateway.core.block import BlockReason

logger = logging.getLogger(__name__)


@dataclass
class FunctionCallCheckResult:
    """Result of a function-call hallucination check."""
    decision: SafetyDecision
    tool_name: Optional[str] = None
    message: str = ""
    rule_name: Optional[str] = None


class FunctionCallDetector:
    """
    Evaluates LLM-proposed tool calls for hallucination.

    Pipeline position: Between Guardian fast-mode (L2) and BYOC (L3).
    Activates only when: tool_calls present AND provenance.is_low_trust.
    """

    def __init__(
        self,
        rules_path: str,
        guardian: Optional[GuardianGuard] = None,
    ):
        """
        Initialize the detector.

        Args:
            rules_path: Path to function_call_rules.yaml
            guardian: Optional pre-configured GuardianGuard instance.
                      If None, one is created from rules config.
        """
        self.rules = self._load_rules(rules_path)
        self.guardian = guardian or self._create_guardian_from_rules()

    def _load_rules(self, path: str) -> Dict[str, Any]:
        """Load rules from YAML file."""
        try:
            with open(path, "r") as f:
                return yaml.safe_load(f) or {}
        except Exception as e:
            logger.error(f"Failed to load function_call rules from {path}: {e}")
            return {}

    def _create_guardian_from_rules(self) -> GuardianGuard:
        """Create a GuardianGuard instance from loaded rules config."""
        rules = self.rules
        fail_strategy = rules.get("fail_strategy", "block")
        timeout = rules.get("timeout_seconds", 5)
        # Guardian URL comes from environment or is derived from GUARDIAN_URL
        # (same as existing GuardianGuard pattern)
        return GuardianGuard(
            url="http://localhost:8000/guardian",
            model="granite4.1-guardian",
            fail_strategy=fail_strategy,
        )

    def should_check(self, tool_calls: List[dict], provenance) -> bool:
        """
        Determine whether the detector should run for this request.

        Args:
            tool_calls: List of tool call dicts from LLM response.
            provenance: Provenance dataclass instance.

        Returns:
            True if detector should run, False if skip.
        """
        if not tool_calls:
            return False

        # Check per-tool overrides first
        tool_names = {tc.get("name") for tc in tool_calls}
        tool_overrides = self.rules.get("tool_overrides", {})
        any_forced = any(
            tool_overrides.get(name, {}).get("enforce", False)
            for name in tool_names
        )
        if any_forced:
            return True

        # Check provenance trust level
        threshold = self.rules.get("low_trust_threshold", 0.5)
        return provenance.trust_level < threshold

    async def check(
        self,
        tool_calls: List[dict],
        provenance,
    ) -> FunctionCallCheckResult:
        """
        Check tool calls for hallucination via Guardian API.

        Args:
            tool_calls: List of {"name": str, "arguments": str} dicts.
            provenance: Provenance dataclass instance.

        Returns:
            FunctionCallCheckResult with decision.
        """
        if not self.should_check(tool_calls, provenance):
            return FunctionCallCheckResult(
                decision=SafetyDecision.ALLOW,
                message="Skipped: no tool calls or high-trust provenance",
            )

        # Build Guardian payload for function-hallucination check
        payload = self._build_payload(tool_calls)

        try:
            async with httpx.AsyncClient(
                timeout=self.rules.get("timeout_seconds", 5)
            ) as client:
                response = await client.post(
                    f"{self.guardian.url}",
                    json=payload,
                )

                if response.status_code == 200:
                    data = response.json()
                    score = data.get("score", "").lower()

                    if score == "yes":
                        return FunctionCallCheckResult(
                            decision=SafetyDecision.ALLOW,
                            message="Function calls validated as legitimate",
                        )
                    elif score == "no":
                        return FunctionCallCheckResult(
                            decision=SafetyDecision.BLOCK,
                            rule_name="function_call_hallucination",
                            message="Guardian flagged tool calls as potentially hallucinated",
                        )
                else:
                    logger.warning(
                        "Guardian API returned unexpected status: %d",
                        response.status_code,
                    )
                    return await self._handle_failure()

        except (httpx.RequestError, httpx.TimeoutException) as e:
            logger.warning("Function-call check failed: %s", str(e))
            return await self._handle_failure()
        except Exception as e:
            logger.exception("Unexpected error in FunctionCallDetector: %s", str(e))
            return await self._handle_failure()

    def _build_payload(self, tool_calls: List[dict]) -> dict:
        """Build Guardian API payload for function-hallucination check."""
        return {
            "tool_calls": tool_calls,
            "model": self.guardian.model,
            "check_type": "function_hallucination",
        }

    async def _handle_failure(self) -> FunctionCallCheckResult:
        """Fail-safe: applies configured fail_strategy."""
        fail_strategy = self.rules.get("fail_strategy", "block")

        if fail_strategy == "block":
            logger.critical(
                "Function-call detector FAIL-CLOSED: blocking request"
            )
            return FunctionCallCheckResult(
                decision=SafetyDecision.BLOCK,
                message="Function-call check failed (fail-close)",
            )
        elif fail_strategy == "allow":
            logger.warning(
                "Function-call detector FAIL-OPEN: allowing request"
            )
            return FunctionCallCheckResult(
                decision=SafetyDecision.ALLOW,
                message="Function-call check skipped (fail-open)",
            )
        elif fail_strategy == "warn":
            logger.warning(
                "Function-call detector AUDIT-MODE: allowing with warning"
            )
            return FunctionCallCheckResult(
                decision=SafetyDecision.WARNING,
                message="Function-call check skipped (audit mode)",
            )
        else:
            return FunctionCallCheckResult(
                decision=SafetyDecision.BLOCK,
                message="Function-call check failed (default block)",
            )
```

#### 2.2 Design Rationale

| Design Choice | Rationale |
|---|---|
| Reuses `GuardianGuard` | Same API, same connection handling, same fail-safe strategies. No new HTTP client code. |
| Separate `FunctionCallDetector` class | Keeps detector logic isolated, testable, and configurable independently from general Guardian scoring. |
| `should_check()` method | Centralized decision logic — proxy calls this first to skip when unnecessary (no tool calls or high trust). |
| `FunctionCallCheckResult` dataclass | Consistent with `BYOCCheckResult` pattern — carries decision, rule_name, and message. |
| Fail-safe strategies match Guardian | Existing `GuardianGuard._handle_failure()` uses the same 4 strategies; detector reuses the same mental model. |
| `timeout_seconds` config | Shorter than thinking mode (5s vs 30s) — this is a lightweight pre-execution check. |

#### 4.4 `_extract_tool_calls()` Helper Method

Add a new private method to `LLMProxy`:

```python
def _extract_tool_calls(self, body: dict) -> Optional[List[dict]]:
    """
    Extract tool calls from an LLM API request/response body.

    Handles Anthropic-style (tool_use blocks) and OpenAI-style (tool_calls) formats.

    Returns:
        List of {"name": str, "arguments": str} dicts, or None if no tool calls found.
    """
    messages = body.get("messages", [])
    if not isinstance(messages, list):
        return None

    for msg in messages:
        if not isinstance(msg, dict):
            continue

        # OpenAI-style: messages with "tool_calls" array
        if "tool_calls" in msg and isinstance(msg["tool_calls"], list):
            tool_calls = []
            for tc in msg["tool_calls"]:
                if isinstance(tc, dict):
                    name = tc.get("function", {}).get("name") or tc.get("name", "")
                    args = tc.get("function", {}).get("arguments", "") or tc.get("arguments", "")
                    if name and args:
                        tool_calls.append({"name": name, "arguments": args})
            if tool_calls:
                return tool_calls

        # Anthropic-style: content blocks with "tool_use" type
        content = msg.get("content", "")
        if isinstance(content, list):
            for block in content:
                if isinstance(block, dict) and block.get("type") == "tool_use":
                    name = block.get("name", "")
                    input_str = json.dumps(block.get("input", {}))
                    if name and input_str:
                        return [{"name": name, "arguments": input_str}]

    return None
```

## 7. Integration Points & Dependencies

### 7.1 Dependencies

| Dependency | How Used | Notes |
|---|---|---|
| `GuardianGuard` | Reuses for Guardian API calls | Same URL, same model, same fail-safe patterns |
| `Provenance` | Checks `trust_level` via `.is_low_trust` | Uses existing property (trust < 0.5) |

| `generate_block_response()` | Produces 403 on block | No changes needed — accepts any reason string |
| `AuditLogger.log_event()` | Logs block/warn events | Existing method, new component name |
| `LLMProxy` | Pipeline integration | `detector` parameter added to `__init__` |

### 7.2 Pipeline Ordering

```
Layer 1 (PII Scanner) → Layer 2 (Guardian Fast) → 4.1 (Function-Call Detector) → Layer 3 (BYOC) → Layer 4 (HITL) → Forward
```

The detector is placed between Guardian and BYOC because:
1. Guardian fast-mode already checked the general prompt safety
2. The detector narrows to *tool-call-specific* hallucination (a different check)
3. BYOC should not see hallucinated tool calls — they're blocked before reaching BYOC
4. If the detector blocks, BYOC never runs (correct — the tool call is already invalid)

## 9. Risk & Mitigation

| Risk | Impact | Mitigation |
|---|---|---|
| Guardian API latency adds to request time | Moderate (adds ~2-5s per check) | Configurable timeout (5s default); skip when not needed |
| False positives on low-trust provenance | Low-Moderate (blocks legitimate tool calls) | Configurable threshold; `tool_overrides` for per-tool tuning; `warn` fail-safe in staging |
| Breaking change to `LLMProxy.__init__` | Low (new optional parameter) | Parameter is `Optional[FunctionCallDetector] = None` — backward compatible |
| Guardian API format change | Moderate (payload shape may differ) | Isolated in `_build_payload()` — single place to update |
| Test mock complexity | Low | Follows existing `test_guardrail.py` patterns; fixtures in conftest |
